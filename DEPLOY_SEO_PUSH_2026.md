## На компьютере отца — локально (Windows CMD)

Распаковать ZIP **в корень `C:\Users\ШУМ\WORKS\perevozki` с заменой файлов**, не создавать вложенную папку. Перенести только файлы из патча, `.env` и `prisma/dev.db` не заменять.

В корне проекта:

```bat
npm ci
npx prisma migrate deploy
npx prisma generate
npx web-push generate-vapid-keys
```

Скопируйте public/private в существующий `.env`. Для локальной разработки `APP_ORIGIN=http://localhost:3000`, production-значения указаны ниже. Используйте **одну постоянную VAPID-пару** для всех устройств этой инсталляции. Не коммитьте ключи.

Удалите устаревший SMTP-модуль (его вызовов уже нет):

```bat
git rm src/services/mail.service.js
```

Проверка синтаксиса:

```bat
node --test tests/seo-push.test.js
npm test
```

**Не выполняйте `migrate reset` или `db push --force-reset`: это удалит заявки.**

## Настройка продакшн-сервера

1. Снимите резервную копию `.env` и **SQLite-БД**, затем обновите код с Git. Убедитесь, что `origin` на компьютере отца — `Dimas-Shumil/SvoiGruzi`; `upstream` не трогать.
2. Убедитесь, что Nginx настроен на `svoi-perevozki.ru` и `www.svoi-perevozki.ru`, и выпущен действительный TLS-сертификат **для обоих имён**. Только `https://svoi-perevozki.ru` должен быть каноническим; www должен возвращать 301 на основной домен. При необходимости адаптируйте `deploy/nginx-svoi-gruzi.conf.example` **под реальный сервер**, не заменяйте действующий конфиг без сравнения.
3. Обновите **существующий** `.env`:

```dotenv
NODE_ENV=production
HOST=127.0.0.1
APP_ORIGIN=https://svoi-perevozki.ru
TRUST_PROXY=1
VAPID_PUBLIC_KEY=... # сгенерированный publicKey
VAPID_PRIVATE_KEY=... # сгенерированный privateKey
VAPID_SUBJECT=mailto:your-working-email@example.com
```

4. Удалите старые `SMTP_*` и `TO_EMAIL` из `.env` (больше не используются). Не присылайте приватный ключ в чат.
5. Запустите из каталога проекта:

```bash
npm ci
npx prisma migrate deploy
npx prisma generate
pm2 restart <фактическое-имя-PM2> --update-env
```

6. Проверьте `curl -I https://svoi-perevozki.ru/`, `curl -I https://svoi-perevozki.ru/sitemap.xml`, `curl -I https://svoi-perevozki.ru/control/push-sw.js`, и 301 на `www`/`index.html`.
7. На HTTPS откройте админку → **Настройки** → **Включить** → **Проверить**. С каждого ПК/телефона разрешение требуется **отдельно**. После этого отправьте тестовую заявку и убедитесь, что она появилась в CRM и пришёл push.
8. На iPhone/iPad нужна iOS 16.4+ и установка на экран «Домой» через Safari; открыть админку именно из установленного приложения. На Android и ПК достаточно совместимого браузера с разрешением уведомлений.

Для `/control/push-sw.js` отдавайте `application/javascript` и `200`. В CSP используется `default-src 'self'`: воркер того же origin.

## SEO после публикации

- Добавить `https://svoi-perevozki.ru` в Яндекс Вебмастер и Google Search Console (при необходимости). Проверить `robots.txt`, отправить `sitemap.xml` и запросить обход главной/автопарка/карточек.
- Заполнить и подтвердить карточку Яндекс Бизнес (адрес или корректно установленная зона обслуживания, телефон, часы, фотографии, категории). Для локального SEO необходимы проверяемые данные.
- Проверить реальные изображения `/site/img/hero-back.webp`, `/site/img/about.png`, `/site/img/autopark-hero.webp` на сервере: присланный архив не содержит исходных изображений. Изображения OG в метаданных должны отдавать 200.
- Измерить Lighthouse mobile / Web Vitals, поисковые сниппеты, CTR и позиции после индексации. «100/100» без опубликованного сервера и замеров подтвердить нельзя.
- В ZIP исходного сайта пусты `site/privacy-policy.html` и `site/offer.html`. **Необходимо утвердить и опубликовать** юридические страницы с реальными реквизитами оператора до публичной рекламной кампании. Мы не выдумывали данные ИП/ООО.
- Контент 15 лет опыта и 1 000+ перевозок взят из исходного сайта; подтвердить перед запуском.
- Не гарантируются специальные AI-rich results: Google не требует отдельного «AI-файла» или GEO-разметки. Основой остаются видимые ответы и качественный локальный контент.

## Примечания по совместимости и приватности

- Письма больше не отправляются, но даже при отключенном/неработающем Web Push **заявка сохраняется в базе** и возвращается пользователю успешный ответ.
- В пуше на экране блокировки **нет телефона и адреса клиента**: только номер заказа и вид груза; детали доступны после авторизации.
- Если заменить VAPID-ключи, все устройства придется переподписать. Для тестового и рабочего серверов рекомендуются отдельные VAPID-пары.
- Эксплуатация Web Push зависит от служб браузера, разрешений ОС и энергосбережения; гарантировать доставку каждого сообщения нельзя. CRM остаётся источником истины.
