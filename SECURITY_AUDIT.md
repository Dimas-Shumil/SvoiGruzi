# SECURITY AUDIT — контрольная точка 2026-10-11

## Исправлено в этом патче

- Node.js по умолчанию и в production слушает только `127.0.0.1`, а не `0.0.0.0`.
- Production-конфигурация запрещает запуск без HTTPS `APP_ORIGIN` и без `TRUST_PROXY=1` за Nginx.
- Для production session-cookie получает префикс `__Host-`, остаётся `HttpOnly`, `Secure`, `SameSite=Strict`.
- Просроченная/невалидная session-cookie удаляется.
- `/control/app.html` больше нельзя получить без авторизации.
- Для `/control` добавлены `no-store`, `noindex` и строгий CSP.
- API помечен `X-Robots-Tag: noindex`.
- Уменьшены лимиты JSON/form body до 64 KB и количество form-параметров до 50.
- Публичная форма защищена rate-limit + same-origin проверкой + honeypot.
- Публичный API автопарка больше не раскрывает идентификатор и персональные данные партнёра.
- Slug машины валидируется по allowlist-формату.
- Имя, маршрут, дата и телефон валидируются на сервере; дата в прошлом отклоняется.
- SMTP использует TLS >= 1.2 и таймауты; ошибка SMTP не ломает сохранение заявки.
- Публичный ответ больше не раскрывает последовательный ID заявки.
- HTML-письмо экранирует пользовательские данные и не показывает номер заявки.
- Добавлены PM2-конфигурация и безопасный Nginx-шаблон.
- Добавлена инструкция UFW: наружу не открывать Node-порт 3000.
- `.env`, SQLite, backups и служебные файлы уже исключены из Git; Node раздаёт только явно разрешённые public paths.
- `/site/sass` и прочие исходники больше не раздаются браузеру через общий static-каталог.

## Что уже было хорошо до патча

- Prisma вместо конкатенации SQL.
- Argon2id для паролей.
- Случайные session tokens хранятся в БД только в SHA-256 виде.
- CSRF-token привязан к session token через HMAC.
- Origin protection на мутациях.
- Login и public request rate limits.
- Helmet и скрытый `X-Powered-By`.
- Ошибки 5xx не возвращают stack trace клиенту.
- SMTP-сбой не откатывает уже сохранённую заявку.

## Не является задачей кода и выполняется при деплое

- UFW / firewall VPS.
- SSH keys, отключение password auth/root login.
- fail2ban.
- TLS-сертификат Let's Encrypt.
- проверка `ss -lntup`, что Node слушает только `127.0.0.1:3000`.
- финальный `npm audit` на машине с доступом к npm registry.

## Дополнительно закрыто в финальной CRM

- Все разделы `/api/control/*` доступны только после серверной сессии.
- Все мутации CRM требуют одновременно корректный Origin и CSRF-token.
- Автопарк и партнёры не доступны анонимному пользователю.
- Удаление клиента — soft delete: история заявок не теряется.
- Удаление машины с историей переводит её в скрытое/недоступное состояние вместо разрушения связей.
- Удаление партнёра с машинами отключает партнёра и скрывает его транспорт вместо потери истории.
- Изображения автопарка загружаются только после авторизации; принимаются только JPG/PNG/WebP до 5 МБ, проверяется сигнатура, имя файла генерирует сервер, произвольный путь записи невозможен.
- SVG/HTML через загрузчик не принимаются; каталог загрузок раздаётся только как часть `/site/img` с `X-Content-Type-Options: nosniff` от Helmet.
- Клиентские данные при рендеринге CRM экранируются перед вставкой в HTML.

## Текущая готовность

Публичный frontend, приём заявок, SMTP, CRM, клиенты, автопарк, партнёры, задачи, финансы и журнал активности реализованы. Публичный автопарк получает опубликованные машины из БД.

Перед production остаются инфраструктурные шаги: реальный домен/SSL, UFW/SSH hardening, финальный `npm audit`, резервное копирование и заполнение SEO/юридических файлов реальными данными.
